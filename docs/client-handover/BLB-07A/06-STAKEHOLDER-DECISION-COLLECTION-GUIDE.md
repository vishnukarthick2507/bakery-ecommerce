# 06 — Stakeholder Decision Collection Guide

**Project:** Bluebell Bakehouse / S.V. Sweets & Bakers  
**Milestone:** BLB-07A — Stakeholder Decision Collection & Approval Request Pack  
**Date:** 2026-11-21  
**Status:** DRAFT — NOT SENT

## 1. Purpose

Guide the project team in collecting, verifying, and recording stakeholder decisions/authorizations without fabricating approvals or crossing execution boundaries.

## 2. Collection workflow

1. **Prepare** — Use BLB-07A docs 01-04 as request drafts; fill placeholders (stakeholder names, dates, channels).
2. **Send** — Only after internal review; send via approved business channel. *BLB-07A does not send communications.*
3. **Receive** — Store evidence in controlled repo location (future BLB intake milestone) or secure reference; record source, date, sender.
4. **Verify** — Check authenticity, approver identity, authority, date, exact decision, selected option, conditions, scope, environment, validity.
5. **Classify** — RECEIVED — NOT VERIFIED / VERIFIED — DECISION CONFIRMED / VERIFIED — CONDITIONAL DECISION / VERIFIED — REJECTED / VERIFIED — DEFERRED / AMBIGUOUS — CLARIFICATION REQUIRED / CONFLICTING EVIDENCE.
6. **Record** — Update decision register (future BLB-04E/06B-style intake) without overwriting prior registers.
7. **Gate** — Do not treat decision as execution authorization. Obtain separate operation-specific authorization before any execution.

## 4. Handling rules

- **Missing required info:** classify RECEIVED — NOT VERIFIED or AMBIGUOUS; request clarification.
- **Conflicting responses:** CONFLICTING EVIDENCE; escalate to decision owner; do not pick one silently.
- **Conditional approval:** record conditions; block dependent execution until conditions verified.
- **General approval:** not sufficient for operation-specific execution. Request separate op auth.
- **Production release:** never inferred; requires explicit D-19 authorization after all gates.

## 5. Prioritization

1. W01 legal/compliance consent decision (P0).
2. Business owner decisions for 19 areas / 21 rows.
3. D-14 infrastructure evidence.
4. Operation-specific execution authorizations (only when decisions/gates ready).

## 6. Communication standards

- Professional, clear, non-blaming.
- Explain why needed and impact of delay.
- Keep business requests plain-language; legal/infra requests technically precise.
- State clearly: production release remains NO-GO; no approvals fabricated.
